# rp-app documentation

[繁體中文](README.md) | **English**

Two parts:

1. **Headless wireless boot**: get a Raspberry Pi 2 Model B online over a USB Wi-Fi adapter with SSH enabled on first boot — no network cable, no monitor — entirely from scripts on a Mac.
2. **Edge Security Gateway** (Rust): firewall baseline, VPN exit node, DNS firewall, IoT AP, observation agent and a policy-controlled MCP server.

Deployment status and to-dos for this device: [status.en.md](status.en.md).

## Environment

| Item | Details |
|---|---|
| Host | Raspberry Pi 2 Model B (BCM2836, 32-bit only) |
| Wi-Fi adapter | Edimax EW-7811Un (Realtek RTL8188CUS, driver `rtl8192cu`, **2.4 GHz only**) |
| OS | Raspberry Pi OS Lite (32-bit, armhf), Debian 13 trixie |
| First-boot configuration | cloud-init (NoCloud; reads `user-data`, `network-config`, `meta-data` from the boot partition) |
| Network management | NetworkManager (configuration generated by netplan) |
| Workstation | macOS with `curl`, `xz`, `shasum`, `openssl`, `python3`, `diskutil` |

## Why not the old OS or a USB cable

- The Pi 2's USB controller is host-only and **does not support USB gadget mode**, so a single USB cable cannot provide both power and networking.
- The 2015 Raspbian originally on the card cannot read Wi-Fi settings from the boot partition; changing Wi-Fi would mean writing the ext4 rootfs, which macOS cannot do by default.
- So the card is re-imaged with current Pi OS and cloud-init settings go on the boot partition (FAT, writable from a Mac).

## Handling secrets

- All real values (account, password, Wi-Fi SSID and password, disk id) live only in `rp_app/local.env`, which is in `.gitignore`.
- Docs and commits use placeholders only, e.g. `<PI_USER>`, `<WIFI_SSID>`.
- The login password is written to the card only as a SHA-512 hash; **the Wi-Fi password is stored in plain text on the boot partition** (a cloud-init limitation), so keep the card safe.
